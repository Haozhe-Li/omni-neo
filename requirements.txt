# For building agents
# Pinned EXACTLY, not to a minor line. Two reasons, and the second is the
# binding one:
#
# 1. core/agent.py registers a HarnessProfile, and `deepagents.profiles` is a
#    documented beta API that may change shape.
# 2. deepagents appends ~1,525 tokens of its own sections (`## write_todos`,
#    `## Skills System`, `## Filesystem Tools`, `## Large Tool Results`) to
#    every system prompt at request time. A fine-tuned adapter is trained on
#    that assembled text, so a patch-level deepagents bump silently changes the
#    prompt the model is served and quietly degrades it. See
#    finetune/pro_agent/fingerprint.py, which hashes the assembled result.
#
# NOTE: this line previously read `>=0.6.12,<0.7` while the environment had
# 0.6.10 installed — the declared floor was never actually satisfied here, and
# every eval baseline on file was measured on 0.6.10. Pinned to what was
# measured rather than upgraded; whatever motivated the 0.6.12 floor is worth
# re-checking before moving off this version, and moving off it means
# re-blessing the fingerprint and re-collecting any training data.

# For coding sandbox
#
# Both pinned exactly, and `e2b` is listed even though it is only a transitive
# dependency of e2b-code-interpreter — because `e2b` is the half that broke.
#
# Production hit `Sandbox error: get_transport() got an unexpected keyword
# argument 'http2'` on gpt-5.6-luna while this same file installed a working
# combination locally. e2b-code-interpreter >= 2.7.0 calls
# `e2b.api.client_sync.get_transport(config, http2=False)`; that parameter only
# exists in e2b >= 2.23.1. Every published pairing declares a floor on the safe
# side of that boundary, so pip cannot resolve the broken combination from a
# clean install — which means the environment that produced it was not built
# cleanly (a cached image layer, --no-deps, or another package holding `e2b`
# back). Naming `e2b` here makes the resolver state explicit instead of leaving
# it to whatever the transitive graph happened to settle on at build time.
#
# These two versions are the pair verified working together: run_python
# returned real output on them. Bumping either means re-testing the tool, not
# just the install.

e2b-code-interpreter==2.8.0
